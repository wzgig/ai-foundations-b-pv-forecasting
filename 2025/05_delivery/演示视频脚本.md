# 3 分钟演示视频录制指南与旁白

视频目标：在 3 分钟左右完整展示“环境搭建 -> 一键启动 -> 项目运行链路 -> 功能演示 -> 核心结果 -> 后续提交材料”的闭环。重点不是现场长时间训练，而是让老师看到项目能启动、能复现、能解释结果、能追溯代码和输出。

建议标题口播：`光伏电站日前功率预测与运行工作台项目演示`。

## 录制前准备

1. 关闭无关窗口、浏览器标签和任何可能出现密钥的页面。
2. 浏览器缩放保持 100%，录屏分辨率建议 1920x1080，导出 MP4。
3. 打开项目根目录：

```powershell
cd "D:\Qiuhua Wang\个人资料\电气\人工智能基础B\电气工程及其自动化+2307+202310080241+王子成+光伏电站日前功率预测与运行工作台"
```

4. 录制前先确认依赖和输出可读：

```powershell
pip install -r 2025\requirements.txt
python 2025\tools\project_health_check.py
python -m unittest discover -s tests -q
python 2025\run_project.py --show all
```

5. 录制时不建议现场完整重训全部模型。3 分钟视频中用 `--show all` 展示已有结果，用 `--dry-run` 展示可运行计划，用工作台“训练控制”展示后台训练入口。若必须展示真实训练，建议只演示局地校正单模型轻量运行：

```powershell
python 2025\run_project.py --run 4 --q4-modes mixed --q4-models FusionModel --q4-fast --epochs 2 --patience 1
```

6. 本项目没有外部网页爬取模块，不要说“爬取网站数据”。可以说“读取本地站点功率、NWP 和 LMD 数据，并从 outputs 中抓取指标、图表和运行摘要展示到工作台”。

## 旁白完整版

下面是一段可以直接照读的 3 分钟旁白：

> 大家好，我展示的项目是“光伏电站日前功率预测与运行工作台”。项目面向电气工程中的光伏日前发电计划场景，目标是利用历史功率、数值天气预报 NWP 和局地气象 LMD 数据，预测未来一天 96 个 15 分钟功率点，为调度计划、运行复盘和模型维护提供依据。
>
> 首先看项目结构。`2025` 目录下保留课程材料、正式工程链路、图表资源、报告材料、运行解读模块和工具脚本。正式代码主要在 `02_problem_solutions`，交付材料在 `05_delivery`，所有重要修改都记录在 `PROJECT_LOG.md`。
>
> 环境搭建使用固定版本依赖，运行 `pip install -r 2025\requirements.txt`。之后执行 `project_health_check.py` 和单元测试，确认代码语法、输入路径、输出管理和网页材料都正常。这些检查不会触发长时间训练。
>
> 项目提供一键启动入口。演示时可以双击 `start_software.vbs`，它会打开桌面启动器并启动本地 Streamlit 工作台；如果需要查看命令行日志，也可以运行 `run.bat` 或 `python -m streamlit run 2025\app.py`。
>
> 工作台首页按工程角色组织结果，而不是按题号堆叠。历史功率基线用于没有未来天气时的保底预测；气象预报融合把目标日 NWP 加入模型；局地校正融合进一步比较 NWP、LMD 和 mixed 输入。
>
> 在运行结果页可以看到核心指标。历史功率基线中 FusionModel 的 E_rmse 为 0.0833；加入 NWP 后降到 0.0699；mixed 局地校正输入进一步降到 0.0465，同时 C_R 达到 95.35%，Q_R 达到 99.84%。这说明多源气象信息对光伏日前预测有明显提升。
>
> 代码与命令页展示了项目总控入口 `run_project.py`。它可以用 `--show all` 查看已有输出，用 `--dry-run` 预演运行计划，也可以按链路运行站点机理诊断、历史功率基线、气象融合、运行场景归因和局地校正。这里不做外部网页爬取，系统读取的是本地站点功率、NWP 和 LMD 数据，并从 outputs 中提取指标和图表。
>
> 训练控制页用于需要重训时使用。它会在后台运行训练脚本，显示 Epoch 进度、checkpoint 复用、日志、停止和继续入口。为了保证课堂演示稳定，视频中主要展示 dry-run 和已有结果。
>
> 最后是运行解读和公开页面。运行解读模块会读取真实指标和运行摘要，解释为什么 mixed 输入表现最好；远程接口不可用时也有离线兜底。GitHub Pages 负责公开展示项目摘要、核心指标和本地运行方式。这样项目形成了从数据处理、模型训练、指标评估、交互展示到报告提交的完整闭环。

## 不建议在视频中做的事

- 不展示 API Key、Codex auth、`.env` 或任何私人 token。
- 不说“爬取网页数据”，因为本项目没有外部网页爬虫。
- 不现场完整强制重训全部模型，容易超过 3 分钟。
- 不用“问题二、问题三、问题四”作为主叙事，尽量说“历史功率基线、气象预报融合、局地校正融合”。
- 不打开杂乱的历史工作区作为主线，历史工作区只作为备份和探索材料。
