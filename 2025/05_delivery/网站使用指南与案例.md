# 网站使用指南与案例

## 使用入口

本项目有两个展示入口：

| 入口 | 地址或命令 | 适用场景 |
| --- | --- | --- |
| GitHub Pages 静态页 | `https://wzgig.github.io/ai-foundations-b-pv-forecasting/` | 快速查看项目摘要、核心指标、结果图表和运行命令。 |
| 本地 Streamlit 工作台 | `python -m streamlit run 2025\app.py` | 查看完整指标表、图表、代码入口、运行解读和受控运行。 |

GitHub Pages 不能运行 Python 和 Streamlit，它只用于公开展示。完整交互、代码浏览和运行控制必须在本地工作台中完成。

## 本地启动方式

### 推荐方式：双击启动

```powershell
2025\start_software.vbs
```

该入口会打开桌面启动器，由启动器在后台启动 Streamlit 服务并打开浏览器。演示视频中推荐使用这种方式。

### 调试方式：命令行启动

```powershell
pip install -r 2025\requirements.txt
python -m streamlit run 2025\app.py
```

不要直接运行 `python 2025\app.py`。该命令只会输出正确启动提示，用于避免 Streamlit bare mode 的误导性日志。

## 使用案例

### 案例一：日前计划编制

目标：快速判断下一日光伏发电功率预测曲线是否适合作为调度计划参考。

操作步骤：

1. 打开工作台。
2. 在“运行视角”中选择“日前计划”。
3. 查看气象预报融合和局地校正融合的指标卡。
4. 在“运行结果”页打开预测曲线图和指标表。
5. 优先关注 `E_rmse`、`C_R`、`Q_R` 和单日曲线偏差。

解释：气象预报融合链路将目标日 NWP 纳入输入，适合日前计划；局地校正融合进一步引入 LMD 或 mixed 输入，用于评估更细尺度气象信息对预测精度的收益。

### 案例二：调度复盘

目标：解释某些时段预测偏差较大的原因。

操作步骤：

1. 在“运行视角”选择“调度复盘”。
2. 查看运行场景归因相关图表，例如特征重要性、典型优弱场景、场景分组图。
3. 在“运行解读”中提问：“哪些场景下 NWP 融合的提升最明显？”
4. 对比历史功率基线和气象预报融合的指标差异。

解释：历史功率模型容易延续前一日形态，面对云量、辐照突变时误差会增大。NWP 输入能提供目标日天气信号，因此在天气变化明显时更有价值。

### 案例三：模型维护

目标：判断是否值得引入局地气象数据或重新训练模型。

操作步骤：

1. 在“运行视角”选择“模型维护”。
2. 查看局地校正融合的 NWP、LMD 和 mixed 输入对比。
3. 打开 `Q4_模型输入对比结果.csv`。
4. 如果 mixed 输入稳定优于纯 NWP，说明局地气象接入对该站点有价值。
5. 如需重训，先使用“运行控制”页进行 dry-run，再勾选确认后执行。

解释：当前结果中 `FusionModel_mixed` 的 `E_rmse=0.0465`，明显优于纯 NWP 输入，说明局地校正可以补足粗分辨率天气预报对电站局部云量和辐照变化的描述不足。

### 案例四：课程交付审查

目标：提交前核对材料是否齐全。

操作步骤：

1. 打开“课程交付”页。
2. 查看作业要求、完成度复盘、主报告草稿、测试表、视频脚本和打包清单。
3. 打开“交付引用”页核对报告、代码、运行摘要、指标表和维护日志状态。
4. 运行轻量验证命令：

```powershell
python 2025\tools\project_health_check.py
python -m unittest discover -s tests -q
python 2025\run_project.py --show all
```

5. 确认报告 PDF、视频 MP4 和最终压缩包已生成后，再进行课程平台上传。

## 常见问题

### Pages 打不开 Streamlit 功能怎么办？

这是正常现象。GitHub Pages 是静态托管，只能展示 HTML、图片和链接。请在本地运行 `python -m streamlit run 2025\app.py`。

### 运行解读没有远程接口怎么办？

项目默认有离线规则兜底。即使没有 API 密钥，也能根据本地指标和运行摘要给出解释。远程兼容 HTTP 接口只是增强项，不是演示必需条件。

### 是否需要重新训练？

提交前不建议现场重训。当前仓库已有 checkpoint、预测表、指标表和图表。演示和报告优先读取现有 `outputs/`，除非明确要做新的实验对比。

### 如果压缩包超过 200M 怎么办？

先精简历史工作区和临时文件，保留正式代码、关键权重、指标、图表、报告和视频。若仍超限，应提前与教师沟通，并在报告中附 GitHub 公开仓库链接。
