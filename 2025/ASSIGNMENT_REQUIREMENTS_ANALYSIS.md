### 4.2 附件 1 指标口径

附件 1 要求使用：

- 归一化均方根误差 `E_rmse`。
- 归一化平均绝对误差 `E_mae`。
- 归一化平均误差 `E_me`。
- 相关系数 `r`。
- 准确率 `C_R = (1 - E_rmse) * 100%`。
- 合格率 `Q_R`，即归一化绝对误差小于 0.25 的样本比例。

当前 `_shared/pv_project.py` 中的 `daylight_metrics()` 已按附件口径计算 `E_rmse`、`E_mae`、`E_me`、`r`、`C_R` 和 `Q_R`，这是项目面向 A 题评分的强项。

   - 本地轻量模型：更符合通知偏好，但环境更重。
   - API 调用：实现更快，但需要密钥配置和演示稳定性保障。
   - 规则模板 + 可选 API：最稳，默认能离线运行，报告中说明可接入大模型 API。

2. 界面采用哪种形式：
   - Streamlit：最适合作业演示，开发快，能展示图表、指标和 LLM 解释。
   - CLI 菜单：依赖少，但演示效果弱。
   - HTML 静态页：稳定，但交互能力弱。

3. 最终提交包是否保留历史工作区：
   - 保留：证据完整，但体积风险大。
   - 精简：更符合 200M 限制，但需在 README 和补充材料中解释数据/权重取舍。

## 10. 结论

当前 `2025` 项目已经具备扎实的算法和实验基础，尤其是 A 题四问、附件指标、模型权重、统一输出和工程化入口已经基本成型。若只按 A 题算法要求看，项目完成度较高。

但《人工智能基础B》期末大作业通知的评分重心不是单纯数学建模论文，而是“Python + 深度学习 + 大模型 + 交互展示 + 一键复现 + 报告视频”的课程工程闭环。因此，后续改造应优先补齐 LLM、界面、一键脚本、报告结构、视频脚本、团队分工和压缩包体积控制。只要这些交付短板补齐，现有项目具备冲击优秀档的基础。
