# 工程化运行画像

本文档用于说明本项目作为“光伏电站日前功率预测与运行工作台”的工程边界、数据契约、质量门禁和运行档案口径。它面向复现、维护、演示和后续扩展，避免把系统理解成一次性的静态报告。

## 1. 系统定位

本项目服务光伏电站日前发电计划和运行复盘。系统读取站点历史功率、数值天气预报 NWP 和局地气象 LMD 数据，形成目标日 96 个 15 分钟功率点预测，并将模型指标、预测曲线、运行摘要、代码入口和解释信息集中到本地工作台。

核心目标不是单次跑出一个分数，而是形成可追溯的运行闭环：

| 环节 | 工程输出 | 用途 |
| --- | --- | --- |
| 数据接入 | 站点功率、NWP、LMD、站点容量与时间戳。 | 支撑日前预测和误差复盘。 |
| 模型训练 | `PureLSTM`、`FusionModel`、`BiFusionModel` 及 checkpoint。 | 形成可复用的预测能力。 |
| 指标评估 | 白昼 `E_rmse`、`E_mae`、`E_me`、`r`、`C_R`、`Q_R`。 | 判断预测精度、曲线一致性和合格率。 |
| 运行档案 | CSV、PNG、HTML、`run_summary.json`、维护日志。 | 支撑复现、审计和答辩展示。 |
| 工作台展示 | Streamlit 本地界面与 GitHub Pages 静态页。 | 快速查看结果、代码、图表和运行状态。 |

## 2. 数据契约

正式预测链路遵循严格日前口径：目标日实测功率不能作为输入，模型只能使用目标日前可获得的信息。气象融合链路使用“前一日实测功率 + 目标日 NWP”；局地校正链路比较 `nwp`、`lmd`、`mixed` 三种输入模式。

关键约束如下。

| 约束 | 当前口径 |
| --- | --- |
| 时间分辨率 | 每日 96 个 15 分钟点。 |
| 预测目标 | 目标日 00:00 至 23:45 功率曲线。 |
| 起报时间 | 目标日前一日 00:00。 |
| 白昼筛选 | 根据有效发电时段计算指标，避免夜间样本稀释误差。 |
| 容量归一化 | 默认装机容量 6600 kW，即 6.6 MW。 |
| 输出位置 | 各链路脚本目录下的 `outputs/`，按 `predictions/`、`metrics/`、`figures/`、`reports/` 分层。 |

## 3. 模型链路

系统保留三条核心预测链路，而不是按历史编号组织展示。

| 链路 | 输入 | 主要决策价值 |
| --- | --- | --- |
| 历史功率基线 | 历史功率序列。 | 在未来天气不可用时提供保底预测能力。 |
| 气象预报融合 | 前一日功率 + 目标日 NWP。 | 提前响应目标日辐照、温度、湿度、风速变化。 |
| 局地校正融合 | NWP、LMD、mixed。 | 判断局地气象接入是否能降低粗尺度预报误差。 |

当前最稳定的展示主线是 `FusionModel`。历史功率基线、NWP 气象融合和 mixed 局地校正链路都能用它形成可解释结果；`PureLSTM` 和 `BiFusionModel` 用于提供基线与复杂结构对照。

## 4. 质量门禁

正式修改和展示前建议通过以下门禁。

| 门禁 | 命令 | 通过标准 |
| --- | --- | --- |
| Python 语法 | `python -m py_compile 2025\app.py 2025\run_project.py 2025\tools\project_health_check.py` | 无语法错误。 |
| 项目健康检查 | `python 2025\tools\project_health_check.py` | 无 Python 解析错误、无未解析输入、无受管输出问题。 |
| 回归测试 | `python -m unittest discover -s tests -q` | 测试全部 OK。 |
| 输出可读性 | `python 2025\run_project.py --show all` | 能读取各链路运行摘要、指标表和预测表。 |
| 页面发布 | GitHub Pages build and deployment | 状态为 success 或 built。 |

这些门禁保证系统不仅能展示结果，也能解释结果从哪里来。

## 5. 运行档案口径

项目中的“档案”指可复现证据，而不是单纯的提交材料。一次完整运行应至少保留：

- 预测明细：`outputs/predictions/*.csv`
- 指标表：`outputs/metrics/*.csv`
- 图表：`outputs/figures/*.png` 与必要的交互 HTML
- 运行摘要：`outputs/reports/run_summary.json`
- 模型权重：`models/*.pth`
- 维护记录：根目录 `PROJECT_LOG.md`

本地 Streamlit 工作台负责读取这些档案并做交互展示；GitHub Pages 负责公开展示项目摘要、核心指标、模型口径和本地运行方式。

## 6. 运维与扩展边界

当前系统适合离线复现、演示和小规模扩展。若继续向真实运行辅助工具推进，优先方向如下。

| 方向 | 建议 |
| --- | --- |
| 数据接入 | 增加多站点统一 schema、缺失值监控和气象数据版本标识。 |
| 模型服务 | 将训练脚本与推理接口拆分，增加批量推理和模型注册表。 |
| 指标监控 | 增加按月、按天气类型、按辐照波动性的误差漂移看板。 |
| 可靠性 | 为长时间训练增加任务队列、断点恢复和日志轮转。 |
| 决策支持 | 增加预测置信区间、异常天气告警和偏差归因建议。 |

当前仓库保留原始归档材料，但公开入口、工作台和运行说明均按工程系统口径组织。后续新增功能也应优先落到数据契约、质量门禁和运行档案三条主线中。
